# Publishing to `charlie-protocol-v1`

The public repo is a **filtered publish** of this one, not a branch. The two
histories can never be merged — treat this repo as the source and the public one
as a build output.

## What differs

| | here | public |
|---|---|---|
| `.planning/` | present | stripped from every commit |
| author emails | the committer's real address | rewritten to `needsmorergb@users.noreply.github.com` |
| everything else | identical | identical |

Keeping "everything else identical" is the whole point. If a doc is edited in the
published repo and not here, the next publish silently reverts it — that already
happened once with the spec files and the READMEs.

## The recipe

Work in a throwaway clone so a bad filter cannot damage this repo.

```bash
git clone . /tmp/cp-publish && cd /tmp/cp-publish
FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f --prune-empty \
  --index-filter 'git rm -r --cached --ignore-unmatch -q .planning' \
  --env-filter '
    export GIT_AUTHOR_EMAIL="needsmorergb@users.noreply.github.com"
    export GIT_COMMITTER_EMAIL="needsmorergb@users.noreply.github.com"
  ' -- --all
git remote remove origin
rm -rf .git/refs/original .git/logs && git gc --prune=now
```

Then check, before pushing:

- `git log --all --format='%ae' | sort -u` — one address, the noreply one
- `git log --all --pretty=format: --name-only | grep '^\.planning'` — empty
- every markdown link resolves (the filter breaks links into `.planning/`)
- `python -m unittest discover -s tests -t tests` — all pass

Push to `needsmorergb/charlie-protocol-v1`, branch `main`.

## Post-filter fixup

One file legitimately differs between the two surfaces and must be patched in
the clone after filtering, every time:

```bash
# This repo tracks .planning/, so it can only ignore the generated intel dir.
# The published repo has no .planning/ at all and should ignore it outright, so
# a clone that runs GSD cannot quietly add it back.
sed -i '/^# Generated by/d;/^\.planning\/intel\/$/d' .gitignore
printf '# Planning artifacts live in the working repo, not in the published one.\n.planning/\n' >> .gitignore
git commit -q -am "chore: ignore .planning in the published repo"
```

Nothing else may differ. Anything else showing up in `git diff pub/main HEAD`
that is not a genuine addition means a file was edited in the *published* repo
and never brought back here — fix it **here**, not there.

## Gotchas

Filtering drops commits that touched only `.planning/`, so the public commit
count is much lower than this repo's. Expected, not a lost commit.

The publish **force-pushes**: re-filtering produces new SHAs, so public history
is replaced rather than appended to. Safe only because this repo is the superset
and the public one is a build output with no other contributors. Verify that
before every push:

```bash
git remote add pub https://github.com/needsmorergb/charlie-protocol-v1.git
git fetch pub main
comm -23 <(git ls-tree -r --name-only pub/main | sort) <(git ls-files | sort)
```

Empty output means nothing is being dropped. **Non-empty means stop** — a file
exists publicly that this repo lacks, and force-pushing would delete it.

Never cite a `.planning/` path from a file outside `.planning/`. Such citations
dangle in the published repo; `indexer/reconcile.py` had one and the text had to
be restated in prose instead.
